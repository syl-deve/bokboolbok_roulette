# AGENTS.md

Guidance for coding agents working in this repository.

## Project Overview

**복불복룰렛 (Bokboolbok Roulette)** — a Flutter random-picker app published on Google Play only (Android). Package ID: `com.malee.bokboolbok_roulette`.

Three modes share one participant list:

- **Roulette** — spin the wheel; pick 1..N-1 winners in a row without repeats.
- **Ladder** — ladder game (사다리타기) with editable result slots.
- **Teams** — split participants into 2..N balanced random teams.

The repository holds only the `android/` platform. iOS, web and desktop folders were removed on purpose; do not re-create them.

## Common Commands

```bash
flutter pub get
flutter run                        # on a connected Android device
flutter analyze --no-fatal-infos   # 8 old info lints (withOpacity, curly braces) are known

flutter gen-l10n                   # after editing lib/l10n/*.arb
flutter build appbundle --release  # AAB for Play Console
flutter build apk --release        # APK for sideloading to a test phone
dart run flutter_launcher_icons    # after changing assets/icon/app_icon.png
```

## Architecture

```
lib/
├── main.dart                 # app setup + roulette + shared UI (~2,270 lines)
├── modes/
│   ├── ladder.dart           # ladder logic (generateRungs / ladderPath / ladderMapping) + LadderPanel
│   ├── team_split.dart       # splitIntoTeams + TeamSplitPanel + ModeStepper
│   └── mode_result_dialog.dart  # shared result dialog for ladder and teams
├── design_tokens.dart        # colors from DESIGN.md + per-participant colors
├── app_analytics.dart        # Firebase Analytics wrapper (counts only)
├── result_share.dart         # share result text + Play Store link
├── review_prompter.dart      # in-app review prompt after the 3rd and 10th result
├── iap_service.dart          # "remove_ads_pro" one-time purchase
├── firebase_options.dart     # generated by flutterfire (Android only)
└── l10n/                     # ARB files (ko, en, ja, zh) + generated delegates
test/
├── history_test.dart         # win-history storage format
└── modes_test.dart           # ladder fairness/validity, team balance
```

### Key classes in `lib/main.dart`

| Class | Purpose |
|---|---|
| `AdHelper` | Interstitial ad load/show; runs a callback after the ad (or at once when ad-free) |
| `MyBannerAd` | Bottom banner ad |
| `Player`, `Preset` | Data models |
| `PlayerProvider` | `ChangeNotifier`: participants, presets, win history, ad-free flag, persistence |
| `HomeScreen` / `_HomeScreenState` | Tabs, shared participant section, roulette wheel and spin logic; hosts `LadderPanel` and `TeamSplitPanel` |
| `_PresetSheet`, `_HistorySheet` | Bottom sheets |
| `_WinnerDialog` | Roulette result dialog with "share result" |

Rules that hold across modes:

- Every mode starts through `_runWithAd` (interstitial first, same rule as the roulette).
- While any mode runs (`_isSpinning || _modeBusy`), the participant section is locked with `IgnorePointer`. Panels report busy state through `onBusyChanged`.
- Result dialogs call `ReviewPrompter.onResult(canPrompt: true)` on close and `canPrompt: false` on "again".
- Win history is recorded for the roulette only.

### Ladder fairness

`generateRungs` draws the outcome first as a uniformly random permutation, then builds rungs (random noise rows + bubble-sort correction rows) that produce exactly that outcome. Keep it that way; `test/modes_test.dart` checks that every participant reaches every slot about equally often.

### State management

Provider. `PlayerProvider` is registered at the root with `ChangeNotifierProvider`; read it with `context.watch` / `context.read`.

### Persistence (`SharedPreferences`)

| Key | Type | Content |
|---|---|---|
| `players` | `List<String>` | participant names |
| `presets` | `List<String>` | `presetName\x00player1\x00player2…` |
| `history` | `String` | JSON object `{name: count}`; the legacy `name:count\|…` format is still read |
| `ladder_results` | `List<String>` | edited ladder result slots |
| `isAdFree` | `bool` | PRO purchased |
| `review_result_count`, `review_prompted_threshold` | `int` | in-app review prompt state |

### Localization

ARB files in `lib/l10n/` (`ko`, `en`, `ja`, `zh`); `app_en.arb` is the template, so placeholder metadata (`@key`) goes there. Run `flutter gen-l10n` after edits (config in `l10n.yaml`).

### Analytics

`AppAnalytics` logs counts and actions only: `spin_start`, `result_shown`, `mode_select`, `ladder_start`, `team_split`, `share_tapped`, `share_outcome`, `preset_save`, `preset_load`, `history_clear`, `remove_ads_tap`, `restore_purchase_tap`. **Never log names or any text the user typed.** A new collected data type also needs the Play Console data safety form and `privacy-policy.html` updated.

### Ads and purchases

- Banner at the bottom; interstitial before each roulette/ladder/team run (frequency deliberately unchanged).
- PRO (`remove_ads_pro`) hides all ads.
- AdMob test device ID is hardcoded; production uses real ad unit IDs.

## Android build

- Gradle Kotlin DSL; Kotlin Gradle plugin 2.3.21 with `kotlin { compilerOptions { jvmTarget = JVM_11 } }` (needed by the Firebase Android libraries).
- `com.google.gms.google-services` plugin; `android/app/google-services.json` is committed.
- Min SDK from Flutter (24), target SDK 36, NDK 27.0.12077973, R8 on for release.
- Release signing reads `android/key.properties` + `my-release-key.jks` (both git-ignored; never commit them).

## Firebase and keys

- Firebase project `bokboolbok-roulette` (Android app only); AdMob is linked to it.
- The Android API key in `firebase_options.dart` / `google-services.json` is public by design and is **restricted in Google Cloud** to this package plus three SHA-1 fingerprints (Play app signing, upload key, internal app sharing). If a signing or upload key changes, add its SHA-1 there or Analytics stops working.

## Web pages and store assets

- `privacy-policy.html`, `terms.html`, `app-ads.txt` and the Google site-verification HTML are served by GitHub Pages from the repo root (`https://syl-deve.github.io/bokboolbok_roulette/…`) and linked from Play Console / AdMob. Do not move or rename them.
- `store-screenshots/` holds the Play listing images (phone/tablet × ko/en/ja/zh), made with the `.agents/skills/store-screenshots` skill.

## Gotchas

- Windows PowerShell 5.1 `Set-Content` writes a BOM and can mangle Korean text; edit `pubspec.yaml` and other files with the file tools or bash.
- `dart format lib` also reformats untouched files; format only the files you changed.
